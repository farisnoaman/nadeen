## Commit Conventions

Use **Conventional Commits** for every commit in this repository. Each commit
has a short imperative subject, an explanatory body, and a Sisyphus co-author
trailer so the style is consistent across all agents and the `main` branch.

### Format

```text
<type>(<scope>): <imperative subject>

<explanatory body: what changed and why, wrapped ~72 chars>

Co-Authored-By: Sisyphus <noreply@ohmyopencode.ai>
```

### Types

- `feat`     — new feature or user-facing behavior
- `fix`      — bug fix
- `refactor` — structural change with no behavior change
- `docs`     — documentation only
- `style`    — formatting / whitespace, no logic change
- `test`     — tests only
- `chore`    — tooling, deps, build, CI

### Rules

- Subject: imperative mood, lowercase first word, no trailing period, ~50 chars.
- Use `type(scope):` where scope localizes the change (e.g. `i18n`, `pdf`, `ui`, `auth`).
- Always separate the subject from the body with one blank line.
- Body explains *what* changed and *why*; note user-facing impact and behavior preserved.
- Always end with the trailer `Co-Authored-By: Sisyphus <noreply@ohmyopencode.ai>`.

*Commit message example*

```text
feat(i18n): default the site and PDFs to Arabic

Flip the locale fallback from English to Arabic across the server layout,
the invoice and report PDF routes, the createInvoicePdf default, and the
i18n context default. An explicit ff_lang=en cookie still selects English;
otherwise first-time visitors now get the Arabic/RTL UI and Arabic PDFs.

Co-Authored-By: Sisyphus <noreply@ohmyopencode.ai>
```

*Commit message example*

```text
fix(auth): reject guest rental creation with 401

Return 401 instead of 400 when an unauthenticated request reaches the
rentals API, so the client correctly routes the visitor to sign-in.

Co-Authored-By: Sisyphus <noreply@ohmyopencode.ai>
```
